# Этап 1: Анализ требований GraphRAG на .NET

## 1.1. Бизнес-цели и задачи

### Основная цель
Создание системы GraphRAG (Graph Retrieval-Augmented Generation) с объяснимым искусственным интеллектом (XAI) для поддержки принятия клинических решений (CDSS) в здравоохранении.

### Ключевые бизнес-задачи
1. **Интеллектуальная поддержка врачебных решений**: Предоставление врачам контекстуальной информации из медицинских графов знаний
2. **Обнаружение взаимодействий**: Выявление лекарственных взаимодействий и противопоказаний с объяснением причин
3. **Объяснимость ИИ**: Визуализация путей рассуждения модели для повышения доверия к системе
4. **Интеграция с FHIR**: Автоматический импорт и обработка медицинских данных в формате HL7 FHIR R4
5. **Мультитенантность**: Безопасная изоляция данных между различными медицинскими учреждениями

## 1.2. Сценарии использования

### Use Case 1: Проверка назначения лекарства
**Актор**: Врач  
**Цель**: Проверить безопасность назначения препарата пациенту  
**Сценарий**:
1. Врач вводит запрос: "Можно ли назначить препарат X пациенту с диагнозом Y?"
2. Система извлекает медицинские сущности (препарат, диагноз)
3. Система строит подграф из графа знаний (пациент → диагнозы → противопоказания → препараты)
4. GNN модель ранжирует релевантность узлов графа
5. LLM генерирует ответ на основе графового контекста
6. Система возвращает ответ с визуализацией reasoning path

**Ожидаемый результат**: Ответ "Да" или "Нет" с объяснением и подсветкой важных узлов графа

### Use Case 2: Импорт FHIR данных
**Актор**: Администратор системы  
**Цель**: Загрузить медицинские данные из EHR системы  
**Сценарий**:
1. Администратор загружает FHIR Bundle (JSON)
2. Система парсит ресурсы: Patient, Condition, MedicationRequest, Observation
3. Система создает узлы графа для сущностей
4. Система создает ребра для связей (Patient → hasCondition → Condition)
5. Система генерирует эмбеддинги для текстовых полей
6. Данные сохраняются в PostgreSQL с RLS изоляцией

**Ожидаемый результат**: Данные доступны для запросов в графе знаний

### Use Case 3: Анализ истории пациента
**Актор**: Врач  
**Цель**: Получить сводку по медицинской истории пациента  
**Сценарий**:
1. Врач запрашивает: "Покажи историю пациента John Doe"
2. Система выполняет Cypher запрос для получения подграфа пациента
3. Система выполняет векторный поиск по клиническим заметкам
4. Система объединяет результаты (hybrid search)
5. LLM генерирует структурированную сводку

**Ожидаемый результат**: Хронология диагнозов, назначений и наблюдений

## 1.3. Функциональные требования

### FR-1: Hybrid Search
- Комбинация векторного поиска (pgvector HNSW) и графовых запросов (Apache AGE Cypher)
- Функция `hybrid_search_context()` для получения релевантного контекста
- Параметры: query_vector, entity_list, tenant_id, top_k

### FR-2: GraphRAG Pipeline
- Entity Extraction: NER для извлечения медицинских сущностей из запроса
- Graph Traversal: Cypher запросы для построения подграфа
- Vector Search: KNN поиск релевантных документов
- GNN Scoring: Ранжирование узлов через Graph Attention Network
- Context Building: Формирование промпта для LLM
- Response Generation: Генерация ответа через Semantic Kernel

### FR-3: FHIR Integration
- Поддержка FHIR R4 ресурсов: Patient, Condition, MedicationRequest, Observation
- Автоматический маппинг FHIR → Graph (узлы и ребра)
- Обработка Reference связей между ресурсами
- Поддержка терминологий: SNOMED CT, LOINC, RxNorm

### FR-4: Explainable AI (XAI)
- Извлечение attention weights из GAT модели
- Ранжирование ребер по важности
- Визуализация reasoning path в JSON формате
- Идентификация узлов, повлиявших на ответ

### FR-5: Multi-tenancy & Security
- Row Level Security (RLS) для изоляции данных
- Автоматическая инъекция tenant_id в запросы
- Audit logging (pgaudit)
- SSL/TLS для коммуникации

### FR-6: API Endpoints
- `POST /api/query` - основной RAG endpoint
- `GET /api/explanation/{queryId}` - детальное объяснение
- `POST /api/admin/import-fhir` - импорт FHIR данных
- `GET /api/health` - health check

## 1.4. Нефункциональные требования

### NFR-1: Производительность
- Query Latency: P95 < 2s, P99 < 5s
- Throughput: >100 RPS
- Graph Traversal: <500ms для подграфов до 5000 узлов
- GNN Inference: <300ms
- Vector Search: <100ms для top-k=50

### NFR-2: Масштабируемость
- Поддержка графов >10M узлов
- Партиционирование данных по tenant_id
- Horizontal scaling через Kubernetes
- Connection pooling для PostgreSQL

### NFR-3: Надежность
- Uptime: >99.9%
- Code Coverage: >80%
- Zero critical/high security vulnerabilities
- Automated health checks

### NFR-4: Качество
- Accuracy: >90% на тестовых медицинских запросах
- Factuality: <5% галлюцинаций (через LLM-judge)
- Explainability: >80% пользователей понимают reasoning path
- FHIR Compliance: 100% для поддерживаемых ресурсов

### NFR-5: Безопасность
- HIPAA compliance для медицинских данных
- Шифрование данных at-rest и in-transit
- Audit logging всех операций
- Role-based access control (RBAC)

## 1.6. Форматы данных

### Входные данные
- **FHIR Bundle**: JSON формат по спецификации HL7 FHIR R4
- **Query Request**: JSON с полями query (string), tenant_id (UUID), context (optional)

### Хранение
- **Relational**: PostgreSQL таблицы для документов, пользователей, тенантов
- **Graph**: Apache AGE property graph для медицинских сущностей и связей
- **Vector**: pgvector столбцы для эмбеддингов (float4[] с HNSW индексом)

### Выходные данные
- **Query Response**: JSON с полями response (string), explanation (object), sources (array)
- **Explanation**: JSON с reasoning_path, important_edges, attention_weights

1. ✅ **PostgreSQL 18 доступность**: Использовать PG 17 для начальной разработки, мигрировать на PG 18 после релиза
2. ✅ **Выбор LLM провайдера**: Начать с Azure OpenAI, предусмотреть абстракцию для смены провайдера

4. ❓ **FHIR терминологические серверы**: Нужна ли интеграция с внешними terminology services (напр., Snowstorm для SNOMED)?
5. ❓ **Fine-tuning LLM**: Планируется ли дообучение LLM на медицинских данных или только prompt engineering?

4. ❓ **Compliance требования**: Кроме HIPAA, нужны ли другие сертификации (GDPR, FDA)?
