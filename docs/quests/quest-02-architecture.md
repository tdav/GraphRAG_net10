# Квест 02. Архитектура решения

## Цели

1. Спроектировать высокоуровневую архитектуру системы GraphRAG_net10.
2. Определить слои и их ответственность (API, Application, Domain, Infrastructure).
3. Спроектировать доменные сущности и основные интерфейсы репозиториев.
4. Определить внешние зависимости (БД, графовая БД, векторное хранилище, LLM/эмбеддинги).

## Задачи

1. Уточнить выбор технологий согласно ТЗ:
   - СУБД для хранения документов и служебных данных.
   - Хранилище графа (отдельная граф-БД или реализация графа в реляционной БД).
   - Векторное хранилище (pgvector/Qdrant/Pinecone и т.п.).
   - Поставщик LLM и эмбеддингов (Azure OpenAI / OpenAI / другой).

2. Обновить документ `docs/stages/stage-02-architecture.md`:
   - добавить раздел с диаграммой уровней (словесное описание или ссылка на диаграмму);
   - описать взаимодействие слоёв: API → Application → Domain → Infrastructure;
   - перечислить доменные сущности: Document, Chunk, EntityNode, RelationEdge, Embedding, Conversation и др.;
   - описать интерфейсы репозиториев (IDocumentRepository, IChunkRepository, IGraphRepository, IEmbeddingRepository, IConversationRepository и пр.);
   - описать взаимодействие с LLM/эмбеддинг сервисом и хранилищем эмбеддингов.

3. Спроектировать структуру solution’а (словесно в документе):
   - проект `GraphRAG.Api` (ASP.NET Core Web API);
   - проект `GraphRAG.Application` (use cases, сервисы);
   - проект `GraphRAG.Domain` (сущности и интерфейсы);
   - проект `GraphRAG.Infrastructure` (реализация репозиториев, клиенты БД и LLM);
   - проект `GraphRAG.Tests` (юнит- и интеграционные тесты).

4. Зафиксировать решения по масштабируемости и деплою:
   - контейнеризация (Docker);
   - предполагаемое окружение (Kubernetes/VM/Cloud Service — согласно ТЗ);
   - подход к логированию и мониторингу.

## Критерии завершения

- Документ `docs/stages/stage-02-architecture.md` описывает целевую архитектуру в достаточной степени для начала разработки.
- Определена и зафиксирована структура solution’а и проектов.
- Выбраны и задокументированы основные внешние технологии (БД, графовая БД/графовое представление, векторное хранилище, LLM/эмбеддинги).
- Решения по масштабируемости, логированию и мониторингу зафиксированы на уровне архитектурных принципов.
